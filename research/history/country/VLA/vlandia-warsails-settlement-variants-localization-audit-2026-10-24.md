# 《战帆》聚落地志对瓦兰迪亚地方史的重写：空间异文、经济专门化与简中本地化滞后

**CHC-VLA-GEN｜独立史料批判专题 v0.1｜2026-10-24｜不申请 H 编号｜仅处理瓦兰迪亚相关聚落的跨模块异文**

## 摘要

本稿对项目 Library 中的 \`SandBox.zip\` 与 \`NavalDLC.zip\` 逐 ID 比较官方 \`settlements.xml\`，并比对两份官方简体中文 \`std_settlements_xml-zho-CN.xml\`。在两份模块共同包含的52个瓦兰迪亚聚落 ID 中，全部52个的 \`posX\`、\`posY\` 均不同；16个聚落的 \`gate_posX\`、\`gate_posY\` 不同；12个聚落在 NavalDLC 中新增 \`port_posX\`、\`port_posY\`（SandBox 对应字段不存在）；仅 \`village_V1_2\` 的英文名称值从 Etirfurd 改为 Echarfurd。已比较的对象中 \`owner\` 与 \`culture\` 未变。35个聚落的英文描述发生变化，其中12个改用新的文本键、23个沿用旧键。对这23个旧键，SandBox与NavalDLC简中表里的译文逐条完全相同，因而无法反映新的英文叙述。按本稿的语义分类，18处实质性英文改写没有获得相应的中文内容更新；另有10处实质性改写已通过新键得到新的中文译文，7处仅属小幅措辞或拼写变化。

这些异文不仅涉及海上经济。Drapand、Galend、Meroc新增或强化鲸类捕猎；Nogrent从养羊改写为葡萄酒与渔夫浓汤；Remental从毛皮捕猎和较宽松的男爵统治改写为银矿枯竭后的盐业；Oritan新增瓦兰迪亚雇佣兵与巴旦尼亚相关山民通婚的族源；Oca对奥克斯·霍尔湖沼的排水与筑厅被写入新的征服史；Fregian则新增由瓦兰迪亚男爵排干旧沼泽湖的叙述。由此，**NavalDLC文本层不是简单给旧地志添加船只，而是对聚落位置、资源专门化、边疆防御和地方族源进行了一轮系统重写。**

但不能把模块间文本差异当成卡拉迪亚世界内部先后发生的历史变化。52个共同 ID 的坐标全部不同，说明地图/地理配置发生了广泛重整；两套文本属于同一官方游戏世界的不同模块资料，并非两份独立历史证人。本稿的结论是版本和史料层面的：历史论文必须记录自己使用的文本层，尤其不能把旧版简中译文当成新版英文叙述的准确翻译。

## 一、材料范围与复验方法

### 1.1 直接读取的文件

- \`SandBox.zip\`：\`Modules/SandBox/ModuleData/settlements.xml\`，以及 \`Modules/SandBox/ModuleData/Languages/CNs/std_settlements_xml-zho-CN.xml\`。
- \`NavalDLC.zip\`：\`Modules/NavalDLC/ModuleData/settlements.xml\`，以及 \`Modules/NavalDLC/ModuleData/Languages/CNs/std_settlements_xml-zho-CN.xml\`。
- 用户提供的 \`encyclopedia-zh-cn.md\`：文件卷首声明游戏版本为 Bannerlord \`v1.4.8.119303\`，城镇和普通村庄中文名由 Native 的 \`std_common_strings_xml\` 核对，地志译文来自 SandBox 的简中语言表。它覆盖53座城镇、141个普通村庄，**不含城堡和 castle_village 型村落**。
- 项目现有归档记录将 SandBox 系列资料标注为 v1.4.8.119303、NavalDLC 为 v1.2.8；本次所用 ZIP 没有 \`SubModule.xml\`，不能只凭 ZIP 字节独立重验构建号，故版本号沿用项目归档标签。本文以两个压缩包中实际读取到的 XML 内容为复验对象，不假定其为游戏运行时最终合并后的唯一文本。

Native.zip 当前可见的9个文件不含 \`std_common_strings_xml-zho-CN.xml\`。因此，普通城镇与村庄主名采用用户上传的官方简中百科；城堡辖村的中文称呼在资料缺口处保留未独立核验限制。对 \`village_V1_2\`，两份 SandBox/NavalDLC 简中语言表都含同一名称键 \`Settlements.Settlement.name.village_V1_2\\`，值均为“埃蒂尔菲德”；故可确认两份源语言表沿用旧中文译名，但不能单凭 ZIP 确认目标运行时最终显示结果。

### 1.2 比较口径

以 ID 交集为单位，分别比较：
1. \`text\` 属性的英文正文；
2. \`text\` 属性引用的字符串键；
3. 该键在两份官方简中语言表中的对应译文；
4. \`posX\`、\`posY\`、\`owner\`、\`culture\`、\`gate_posX\`、\`gate_posY\`、\`port_posX\`、\`port_posY\` 与英文 \`name\` 字段。

本稿只报告对瓦兰迪亚聚落 ID 家族（\`town_V*\`、\`village_V*\`、\`castle_V*\`、\`castle_village_V*\`）的审计结果，不将所有大陆的异文混进同一统计。字符串键相同且中文译文相同，是直接可复验的文件事实；“改写是否实质改变历史解释”属于本稿的分析分类，必须公开分类标准，不能伪装成机器自动得出的事实。

### 1.3 证据层级

- **A-XML**：某个官方模块文件确实含有该文本、键或配置。
- **A-CN**：对应的官方简中语言表确实含有该译文。
- **B**：同一聚落在两个模块文本层之间存在可确定的文本差异。
- **C**：对这些差异的社会史、政治史或地理史含义所作的解释。
- **未知**：模块加载时的最终覆盖顺序、缺失的最终显示名键、文本改写的确切开发日期，以及是否存在游戏世界内部的相应事件。

英文和简中来自同一官方文本族，不按两名独立证人计数；SandBox与NavalDLC也不是两部独立的历史编年。尤其不能把“NavalDLC 的文字更详尽”直接理解为“故事中的事件发生在更晚年代”。

## 二、数量结果：空间重整与文本改写

### 2.1 共同聚落 ID 与坐标变化

两份 \`settlements.xml\` 共同包含52个瓦兰迪亚聚落 ID。在这52个 ID 中，**52/52 的 \`posX\` 和 \`posY\` 都与另一份模块文件不同**。在本次检查的字段中，\`owner\` 与 \`culture\` 没有变化。

这足以证明两份资料中的聚落与交通配置存在广泛差异，但不宜进一步说聚落在故事世界里真的迁徙。聚落中心坐标、16组城门坐标和12组新增港口坐标的差异，可以来自地图扩展、场景布置或模块地理配置重整；仅凭这些字段无法区分具体技术原因。相应地，某村庄在一个文本里位于“奥克斯湖边”，在另一文本里位于“特朗河谷”，首先应作为**两套地理配置/文本描述之间的差异**处理，而不是编造一次村民集体迁移。

### 2.2 英文描述与本地化键

35个共同聚落的英文 \`text\` 正文不同：
- **12/35 更换文本键**；
- **23/35 沿用原文本键**。

在23个沿用旧键的条目中，SandBox与NavalDLC简中语言表中的对应文本逐条完全相同。这说明旧译文没有随新英文正文更新。12个更换键的条目中，11个具有新的同键中文文本，但其中加伦（Galend）的新译文仍未加入英文新增的“whalers”（捕鲸者）；其余10个更换键的实质性新内容有对应的新简中译文。

按语义影响分类：
- **18处实质性英文变化没有获得相应中文内容更新**：17处是“正文改了、键没改、中文仍为旧文”，另1处是加伦新键的中文译文仍遗漏捕鲸者。
- **10处实质性变化获得新中文译文**。
- **7处属于轻微措辞、大小写或近似同义的变化**，即便未重译，也没有同等程度地改变历史主张。

这里的“实质性”指地理位置、资源经济、人口/族源、政治控制或地方传说发生变化；不把单纯大小写变化算成历史改写。该分类是可讨论、可复核的研究判断，而不是游戏文件自带的标签。

## 三、具有历史解释力的主要改写

### 3.1 海岸经济：从一般捕鱼到鲸类捕猎与高价值海产

**德拉邦（Drapand，castle_village_V3_1）**：SandBox 只说村民冒险前往北方寒流冲刷的鳕鱼渔场。NavalDLC 则称其为海岸上最重要的航海村落，并说该村名赋予其北方海湾；村民远海捕猎露脊鲸和黑鲸，有时北上至贝恩兰追逐弓头鲸和独角鲸。DLC 的新键 \`K1XMpxea\` 有相应官方简中译文。它不只是增加几种鱼类，而是把该村的经济身份从渔场聚落提升为跨海域远洋捕猎中心。【A-XML/A-CN；C】

**加伦（Galend，town_V5）**：SandBox 说它接收比斯坎渔民的渔获与附近山地绵羊的羊毛。NavalDLC 在英文中新增“whalers”，将鲸类捕猎明确纳入其沿海经济；虽然改用新键 \`UCrwAaba\`，该键的中文译文仍只写渔民，没有翻出捕鲸者。这是“换键不等于译文完全更新”的直接例证。【A-XML/A-CN】

**梅罗克（Meroc，village_V5_2）**：旧文强调鲻鱼、鲈鱼、金枪鱼与沙丁鱼；新文将附近鱼类写成日常口粮，把更远海域的鲸类等猎物写成利润更高的捕猎对象。新键 \`ameOg5g7\` 的官方简中同步更新。这为海岸社会提供了更清晰的**生计捕鱼与高收益远洋捕猎之间的差别**，但不能据此计算捕鲸量、船只数量或港口贸易额。【A-XML/A-CN；C】

**诺格伦（Nogrent，village_V5_3）**：旧文称村民在山坡牧羊；新文改为山脊葡萄酿成醇厚葡萄酒，并成为比斯坎地区渔夫浓汤的重要原料。新键 \`UIrbLGBx\` 有新的中文译文。该改写把海岸经济从“捕鱼+羊毛”延伸到食物供应与葡萄酒生产之间的联系。【A-XML/A-CN；C】

**德里亚特（Deriat，castle_village_V6_2）**：旧文位于瓦尔切格湾与埃博半岛山脊之间，主业是捕河狸、水貂和海豹；新文改在德拉邦湾内陆，改为养猪并赶往高地觅食坚果与根茎。该条仍使用旧键 \`Settlements.Settlement.text.castle_village_V6_2\`，中文保留了旧地理与毛皮/海豹经济。【A-XML/A-CN】这属于经济和空间的实质重写，不是“同一村庄逐步改行”的故事内证据。

### 3.2 矿业与盐业：资源枯竭并不必然意味着聚落衰亡

**西岚达克（Sirindac，castle_village_V5_2）**：旧文只说山间溪流产出富含云母和长石的浅色黏土；新文补充最初的定居者是淘银者，银矿大多枯竭后，当地主要出口供陶工使用的黏土。新键 \`jRaphKwi\` 的官方简中已同步更新。这是一个清楚的资源序列：寻银吸引定居、矿脉枯竭、当地生产转向黏土。它是游戏文本所陈述的地方史，不足以估算矿业持续时间或人口变化。【A-XML/A-CN；C】

**勒芒塔尔（Remental，village_V8_3）**：旧文称当地人诱捕貂、兔、狐，森林的相对自由吸引新移民，瓦兰迪亚男爵的统治比南方宽松；新文则说瓦兰迪亚定居者最初为银矿而来，矿石很快枯竭，后来勘得盐矿。盐在这里很有需求，因为海岸过于陡峭，不适合建设盐田。该条仍使用旧键 \`Settlements.Settlement.text.village_V8_3\`，中文继续显示毛皮捕猎和较宽松男爵统治，而未翻出银矿枯竭与盐业。

这会直接影响此前瓦兰迪亚社会史的证据表述：**“勒芒塔尔的男爵统治比南方宽松”是 SandBox 文本层的明确说法，不是 NavalDLC 文本层对该村的当前描述。** NavalDLC 的相邻村庄卡南克（Cananc，village_V8_2）反而新增“崎岖地带的瓦兰迪亚男爵统治比南方宽松，吸引看重相对自由的移民”这一句。因而，地区性“较轻统治”叙述在新文本中并未完全消失，而是从勒芒塔尔移到了卡南克；旧简中却保留旧版分配。这是需要明确记录的**叙述重分配与本地化错位**，而非证明两个村庄在故事中交换了居民。【A-XML/A-CN；C】

**卡南克（Cananc，village_V8_2）**：新英文仍保留养猪、林地觅食，但把林木由雪松改成紫杉，并增加冷杉、云杉以及较轻男爵统治和移民的描述。旧键与旧简中没有更新，中文仍只写养猪、橡子、栗子和蛴螬。这说明同一地区的新地志更明确地把生态、畜牧、林木资源与地方统治方式放在一起叙述。【A-XML/A-CN；C】

### 3.3 农业扩张与领主的地景改造

**奥克斯·霍尔（Ocs Hall，town_V2）**：SandBox 把莫德里斯湖描述为火山口湖，传说是巨人居所；奥克征服该地，巴旦尼亚部落被驱往内陆并带走传说。NavalDLC 改为一片沼泽池塘，传说是水灵女王的宫廷、当地人曾向其献祭；随后明确说奥克排干池塘开辟农田，并在高地建造大堂，巴旦尼亚部落被驱越莱恩诺山脉。文本键仍为 \`nhmBQIC4\`，中文仍保留“巨人足印”版本，未出现水灵女王、排水开田和筑厅。该改写使征服不只表现为驱逐，也涉及湿地改造、农业扩张和统治中心的物质建造。【A-XML/A-CN；C】

**弗雷吉昂（Fregian，village_V2_3）**：旧文将其放在帕拉汶德以北平原，种植亚麻；新文改为奥克斯·霍尔附近浅谷，明确说沼泽地原为湖泊，由瓦兰迪亚男爵排干后种亚麻。旧键及中文仍保留“帕拉汶德北部平原”的说法。该条与奥克斯·霍尔的新叙述互相呼应：新文本将瓦兰迪亚的领地扩张描绘为包含领主组织的排水工程，而不是只靠军事征服。【A-XML/A-CN；C】

**阿利斯维斯特（Halisvust，village_V9_2）**：两套文本都保留瓦兰迪亚定居者排干沼泽、种植小麦和黑麦的核心叙述；NavalDLC 将地貌具体化为埃博半岛脚下、海岸灌木林中的沼泽。该条沿用旧键，中文仍说“荒芜的沼泽”与“山谷”，所以新增的沿海地理细节未反映出来。它可以支持移民通过水土工程扩张耕地的模型，但不能与弗雷吉昂直接合并为同一次工程。【A-XML/A-CN；C】

**奥曼法德（Ormanfard，castle_village_V4_1）**：旧文写快速河流、湖泊与葡萄梯田；新文将它放在通往巴旦尼亚的奥曼特尔山口脚下，改种小麦和大麦，并说村民警惕守山口城堡传来的号角，以防巴旦尼亚掠袭。新键 \`w6hCZS3K\` 有同步中文译文。这使该地的意义从高价值葡萄酒生产，转向粮食生产与山口防御。【A-XML/A-CN；C】

### 3.4 地方族源与边疆接触

**奥里唐（Oritan，village_V2_2）**：旧文只说河流拐弯处可采陶工黏土；新文则称当地家族追溯其祖先至与巴旦尼亚相关的本地山民通婚的瓦兰迪亚雇佣兵。旧键及中文仍只写河岸采黏土。此处是明确的族源叙述，值得与文化起源史对读，但它不是人口统计，也不能证明所有当地家族有同样祖先。【A-XML；C】

**埃蒂尔菲德／Echarfurd（village_V1_2）**：SandBox 英文名为 \`Etirfurd\`，描述其位于巴旦尼亚边境、埃蒂尔河泉源附近，村民种麦并向驻军出售；NavalDLC 英文名改为 \`Echarfurd\`，描述则改为埃皮尔山丘北坡，称它不同于王国内多数聚落，系瓦兰迪亚移民所建，并以故乡旧地名命名，村民仍种麦并向驻军出售。英文名称键和描述键均沿用旧键，官方中文旧译文仍呈现旧的边境河流故事。该差异同时涉及地名、聚落创立者、迁徙记忆与军需市场。**两份 SandBox/NavalDLC 官方简中语言表都把同一名称键译作“埃蒂尔菲德”。因此这里应记作：英文名称值由 Etirfurd 改为 Echarfurd，简中语言表仍沿用“埃蒂尔菲德”；运行时最终显示值仍须结合模块与语言资源加载证据核实。**【A-XML；中文名未知】

**奥克斯·霍尔**的新文本还说巴旦尼亚部落被赶往莱恩诺山脉以西/越过山脉（原文为 \`over the Rhennod\`），与奥里唐的混合祖源叙述共同显示：边疆征服、人口驱逐和通婚定居并存。它们不能压缩成“瓦兰迪亚人完全替代了巴旦尼亚人”或“所有本地人都被同化”的单线叙述。【C】

### 3.5 其他地理与经济异文

部分改写虽没有新增完整族源或政权事件，却会改变研究者对区域经济与空间关系的理解：
- **于桑克（Usanc，castle_village_V1_1）**：由沙拉斯湾内的一处小海湾改为俯瞰沙拉斯湾的埃皮尔山坡；旧键和中文仍保留小海湾位置。

## 四、这批异文允许提出哪些历史解释？

### 4.1 地方史的主轴从“文化标签”转向“资源—劳动—控制”
NavalDLC 的一组描述把村庄和城镇嵌入具体的资源流：鱼类与鲸类、葡萄酒与渔夫浓汤、盐、黏土、谷物、橄榄、猪和羊。这里能提出的不是“瓦兰迪亚存在统一的出口贸易制度”，而是一个较谨慎的模型：**聚落地志用生态条件、资源采集、劳动方式和周边市场来解释地方的经济功能**。渔民日常捕捞与高收益远洋捕猎被区分，矿业枯竭后盐或黏土成为替代资源，猪饲养又分别依靠橡果林地或沿海谷物。

### 4.2 军事控制不只是城堡和骑兵
奥克斯·霍尔、弗雷吉昂与阿利斯维斯特的文本都涉及排水、沼泽和可耕地；奥曼法德则把山口城堡的号角与村民对掠袭的警惕连在一起。新文本由此允许提出：地方统治的日常基础可能包括**水土改造、粮食生产、边境警戒与驻军需求**，而不仅是封臣出征和城市围城。但目前没有具体劳役、税收、工程组织或司法文件，不能说是国家主持的统一排水计划。

### 4.3 “地方自治/轻统治”必须注明模块与地点
SandBox 对勒芒塔尔的描述强调森林自由和较轻的男爵统治；NavalDLC 把勒芒塔尔改写为矿业—盐业聚落，却在卡南克增写较轻统治和移民吸引力。两者可支持“北部崎岖地区可能提供不同于南方的生活条件”这一待检验假说，但不能合并成一句不注明版本的官方定论。**在不同模块文本中，具体村庄承载的论点发生了迁移。**

### 4.4 族群混合、移民和军事定居并行
奥里唐的瓦兰迪亚佣兵后裔与当地山民通婚、埃查尔福德的瓦兰迪亚移民纪念故乡、奥克斯·霍尔的巴旦尼亚部落被驱逐，构成三种不同的地方人口过程：通婚、迁入命名和征服驱逐。它们不构成同一人口政策，也不证明全瓦兰迪亚按统一方式替换旧人口。与罗瓦尔的诺德移民史合读，更应将瓦兰迪亚社会视作地区差异明显的复合共同体，而非人口来源单一的封闭民族。

## 五、对既有瓦兰迪亚研究的修订要求

1. **《瓦兰迪亚历史初步摸底与重大研究问题》**：原稿把勒芒塔尔的毛皮经济与较轻男爵统治列为地方差异证据；这只适用于 SandBox 文本层。新增本稿链接后，后续总论必须注明 NavalDLC 将该村改写为银矿枯竭后盐业，并把较轻统治的句子加到卡南克。
2. **《西部征服、城市接收与地方权力形成》**：涉及勒芒塔尔北部森林自由、奥克斯·霍尔和排水农业时，应区分 SandBox 与 NavalDLC 两套文本，不将地理描述合并成同一版本的连续地志。
3. **《瓦兰迪亚的土地、佃户与领主司法》**：其关于勒芒塔尔“男爵统治比南方宽松”的引文应标注为 SandBox 版直接史述；NavalDLC 对卡南克的对应描述是另一条聚落级证据，不能因中文译文仍显示旧文而忽略。
4. **《瓦兰迪亚乡村地权、绿林兄弟会与沙拉斯叛乱》**：该稿关于沙拉斯行会、海运粮商和围城证词来自 NavalDLC 对话；不能把其所处的 DLC 文本层与旧版聚落地志自动拼成一条绝对年代链。
5. **《瓦兰迪亚王权的协商与强制》**：沙拉斯“戴·科尔坦男爵”证词和城镇地志同样必须保留模块来源；本稿的地志差异不提供该男爵的个人姓名或围城日期。

上述修订只要求加上版本限定和交叉链接，不要求推翻已经有明确来源支持的论点。没有证据时不把文本差异转化为故事内事件。

## 七、结论

瓦兰迪亚地方史不能只从一套聚落地志中抽取看似稳定的“官方事实”。本次对比表明，两个官方模块中相同的聚落 ID 可以有不同坐标、不同经济叙述、不同地方传说和不同族源说明。某些变化只是措辞，但另一些会改变研究者对地方人口、资源、统治与环境改造的理解；官方简中又未在所有地方同步更新。

因此，后续瓦兰迪亚研究必须在每项地志证据旁标明模块来源和字符串键。**SandBox 版勒芒塔尔的森林自由，不能无标记地当作 NavalDLC 版勒芒塔尔的现行地志；旧简中里关于湖、河、山脉和生计的句子，也不能自动覆盖新的英文描述。** 这是对证据使用方式的校正，不是把开发文本改写误认为卡拉迪亚世界内部的历史事件。

### C.2 对本稿原结论的精确限定

1. **仍然确认的文件事实：** SandBox 与 NavalDLC 的两份 `settlements.xml` 中存在同 ID 的聚落对象，52个瓦兰迪亚聚落的 `posX`/`posY` 全部不同；35个描述正文不同；相应的文本键与简中译文差异已按附录A登记。三个归档文件的 SHA-256 已重新计算，与附录B一致。
2. **可由技术文档支持的机制：** 如果这些文件确实在目标运行模式中注册并共同载入，游戏的 XML 合并机制会处理重复对象，而不是简单地把两个文件当成互不相关的两套百科。重复对象的冲突属性如何定值，须结合注册信息与加载顺序判断。
3. **目前尚不能确认的运行时事实：** 本项目保存的 SandBox.zip 与 NavalDLC.zip 均不包含 `SubModule.xml`，也没有本次游戏运行时的模块启用列表、合并后的 settlements 数据或资源缓存。因此，当前证据仍不足以确认目标构建的具体 XML 注册配置、模块加载顺序、最终合并后的每个属性值，以及游戏内实际显示的最终简中地志。
4. **中文译文的精确表述：** 23个沿用旧键的条目在两个 ZIP 各自的官方简中语言表中确实是同键、同译文；这证明语言表本身未反映对应英文改写，但不能单凭这两个语言表断言运行时语言管理器一定以哪一个表作为最终来源。加伦的 NavalDLC 新键 `UCrwAaba` 对应简中译文仍未翻出英文新增的 whalers，这一语言表内容差异可以直接确认。
5. **坐标结论的边界：** 52组坐标值均不同是数据比较结果；“地图扩展、重投影、布局重整”等只是候选技术解释，尚未证实具体成因。它不证明聚落在世界内迁徙，也不证明最终运行时一定采用全部 NavalDLC 坐标。

### C.3 下一步要取得什么，才能作最终裁定？

至少需要目标安装版本的完整 `Modules/SandBox/SubModule.xml` 与 `Modules/NavalDLC/SubModule.xml`，核对二者对 settlements 的 `XmlNode` 注册及 `IncludedGameTypes`；其次要有启动器/模块清单确认 NavalDLC 是否启用、排序如何；最后最好从同一目标构建提取运行时合并结果，或在游戏内/日志中核对若干区分度高的地志。可优先检查：
- `village_V8_3` 勒芒塔尔：毛皮/森林自由 vs 银矿枯竭/盐业；
- `town_V2` 奥克斯·霍尔：巨人湖传说 vs 水灵女王、排水开田与筑厅；
- `village_V1_2`：Etirfurd vs Echarfurd 的英文显示名，以及同键简中是否仍显示“埃蒂尔菲德”；
- `town_V5` 加伦：是否出现 whalers 对应中文内容。

### C.4 结论措辞修订

因此，本稿的安全结论应写作：**“NavalDLC 与 SandBox 的源文件对相同聚落 ID 提供了不同的地志文本；这些差异具有潜在的运行时合并意义，但在缺少目标版本 SubModule.xml 和运行时加载证据前，本文不宣称已确定游戏内最终采用哪一套内容。”**

此前若把“DLC 版当前地志”理解为“已经确认的运行时最终文本”，应以本补记为准；本文仍可作为可复验的模块源文件异文审计使用，但不冒充完整的运行时加载审计。


## 附录D：名称键复核与前述中文名限制的修订（2026-10-24）
对 `village_V1_2` 的进一步逐键核查发现：SandBox 与 NavalDLC 两份 `std_settlements_xml-zho-CN.xml` 均包含同一个名称键 `Settlements.Settlement.name.village_V1_2`，其中文值都为“埃蒂尔菲德”；两份 `settlements.xml` 的英文名称虽然从 `Etirfurd` 改为 `Echarfurd`，但名称键未改变。因此，**就本次两份官方简中语言表而言，可确认该聚落名称仍译作“埃蒂尔菲德”**；不能擅自另造“埃查尔福德”等译名。更准确的表述是：DLC 英文源文本已改名，而现存同键简中仍沿用旧译名。

这项发现修订了正文第1.1节和第3.4节中“本次资料不足以确认该 DLC 版本主名的最终官方简中形式”的措辞：现有资料足以确认两份 ZIP 内的官方简中名称值，但仍不能单独保证任一实际安装版本的运行时模块注册/语言资源合并情况。此处区分的是“源语言表里明确写了什么”与“目标运行时最终加载了什么”，不能再把二者混为一谈。

同理，加伦 `town_V5` 的新描述键 `UCrwAaba` 在 NavalDLC 简中表中存在明确中文译文，但该译文没有对应英文新增的 `whalers`（捕鲸者）信息。该处应标为“已有同键官方简中，但翻译内容不完整”，而不是“没有新中文译文”。


## 附录E：完整聚落属性差异复核（2026-10-24 补记）
重新枚举52个共同瓦兰迪亚聚落的全部 XML 属性后，发现初版方法部分只列了 `posX`、`posY`、`owner`、`culture`，遗漏了城门和港口位置字段。现补记如下，取代任何“只存在四类字段差异”的理解：

- `posX`：52/52 个 ID 数值不同。
- `posY`：52/52 个 ID 数值不同。
- `gate_posX`、`gate_posY`：16个 ID 的城门坐标发生变化。
- `port_posX`、`port_posY`：12个 ID 在 NavalDLC 中由原版缺省变为有值；本次交集比较未发现原版已有 port 坐标后被改写的情况。
- `text`：35个 ID 的英文描述正文不同。
- `name`：仅 village_V1_2 的英文名称值改变（Etirfurd→Echarfurd），但名称键保持不变。
- `owner`、`culture`：52个共同 ID 中均未发现差异。

这些是逐属性比较的文件事实。尤其是港口坐标新增只能证明 NavalDLC 的聚落数据增加了 `port_posX`/`port_posY` 字段值，不能单凭坐标断言某个聚落在目标运行时已被正确注册为港口、具有可用海路或已在地图场景中启用相应港口功能；还须核对 `SubModule.xml`、场景、船舶/港口相关数据与实际运行时加载结果。

因此，摘要与方法部分已扩充字段范围。初版“坐标全部变化”结论仍成立，但现在应更精确表述为：52组聚落中心坐标全变，16组城门坐标变，12个聚落新增港口坐标，且仅一个英文聚落名值发生变化；所有这些均为模块源文件对比，尚不等于最终运行时状态。


## 附录F：官方 XML 合并机制与本次差异的条件性解释（2026-10-24 补记）

TaleWorlds 官方《Merging Module XML Files with Native》明确写道：Bannerlord v1.3 引入托管 XML 合并算法；例如 `items.xml`、`heroes.xml` 和 `settlements.xml` 由模块根目录的 `SubModule.xml` 中 `XmlNode` 注册；合并算法依据 XSD 中定义的元素唯一属性（官方示例是 Item 的 `id`）匹配已有对象。匹配后可以修改对象的指定属性，未命中的对象则新增；官方例子显示只提交部分属性不会把原对象未提及的属性全部删除。来源：https://moddocs.bannerlord.com/bestpractices/merging_module_xml_files_with_native/ （官方文档，访问于2026-10-24）。

对本研究而言，这意味着不应把 NavalDLC 的 `settlements.xml` 描述成与 SandBox 完全独立、二者择一的整份百科。**若**目标版本的 NavalDLC `SubModule.xml` 注册了同一托管 Settlements XML，并且该运行模式加载此模块，官方机制支持“同一聚落对象按 ID 合并、相应属性被改写/新增”的可能。按源文件差异，条件性预测会是：52个共同 ID 的中心坐标值由合并顺序决定其最终属性值；16个聚落的城门坐标值有差异；12个对象的港口坐标字段可能被补入；35个对象的描述正文会受到同键/新键文本选择的影响；其余未被 DLC 对象改动的属性通常保留在合并对象中。以上是基于官方机制与两个源 XML 的**条件性预测**，不是运行时观察结果。

仍缺少的证据包括：目标构建实际安装的 SandBox 与 NavalDLC 的完整 `SubModule.xml`、其中的 `XmlNode id/path` 与 `IncludedGameTypes`、启动器的启用模块及顺序，以及合并后的对象/语言资源或游戏内实测。当前研究 ZIP 只有选取的 ModuleData XML 和语言表，不包含这些注册文件。官方文档提供通用算法，并不自动证明这些特定归档版本的每一条注册配置。
